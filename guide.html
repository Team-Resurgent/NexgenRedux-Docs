Guide

Your first screen

Download the showcase for your machine, or build it, and look in its media/showcase folder. Each folder there is a screen. Make a new one called hello with two files.

screen.json says how it appears in the menu:

{
  "title": "Hello",
  "description": "My first screen",
  "category": "Games",
  "order": 200
}

main.as is the screen:

class Hello : Screen
{
    Font@ font = Assets::font("global:freesans.sfn", 48);
    float x = 640;

    void update(float dt)
    {
        x += Input::move.x * 300 * dt;
    }

    void draw(Canvas@ c)
    {
        c.design(1280, 720);
        c.circle(x, 360, 80, Blue);
        c.text(font, "Hello", x, 335, White, AlignCenter);
    }
}

Start the showcase with --dev and it reloads the screen each time you save. If there is a mistake, the screen shows the file and the line; mend it, save, and it carries on. A console has no command line: there, put a folder called dev beside the title (in its media), and copy changed scripts and pictures to it over the network, as with an FTP client or the debug monitor. A script can also turn it on, or off, itself with App::development.

Debugging

The VS Code extension in engine/tools/vscode (Nexgen-vscode.vsix in each release) stops a script where you ask it to: set a breakpoint, press F5, and step over, into and out of functions, with the call stack, each frame's locals, the screen's members and the module's globals. Objects open up to what they hold, the engine's own types through their properties; hovering over a name, or typing player.position.x in the Debug Console, shows its value; a script error stops where it happened; and the log is in the Debug Console. Its profiler, on the debug toolbar, shows which functions and lines took the scripts' time. *Run and debug* starts the showcase with --debug 4711 --debug-wait; *Attach* connects to one already started with --debug, which listens on that machine only unless --debug-remote is given. On a console, a folder called debug beside the title lets a computer on the network attach to it.

While it runs, *Nexgen entities* beside the call stack lists the entities of the screen on top, each with its children and what it is like: where it is, how it is turned and big, its colour, model, animation, body and collider. The pencil beside a property changes it there and then, as the game goes on: a robot moved to 1, 5, 2, a body sent off at 0, 8, 0.

To see what touches what, Space::showShapes and Scene::showShapes draw every collider over the picture: grey walls, green bodies (darker asleep), blue walkers and characters, orange ragdolls, yellow areas that only feel. Space::showNavigation draws the squares that Space::navigate found can be walked on. In Guards, Tumble, Topple and Physics, C or the left trigger shows them.

Screens

A screen is a class that implements Screen. The engine calls the methods it has:

MethodWhen
onEnter()Once, when everything the screen asked for has loaded
update(dt)60 times a second, whatever the display does
draw(canvas)Once for each frame shown
onSuspend(), onResume()When another screen opens on top, and closes again
onExit()Once, before it closes

Move in update and draw in draw. Screens form a stack: Screens::push("id") opens one on top, Screens::pop() goes back. Each has its own script module, so nothing is shared by accident, and closing one gives back everything it had. Escape, Start, or holding Back always opens the engine's menu: a script can't block it.

Drawing

Call design(1280, 720) first and draw as if the screen were that size; it is fitted to the real one, with bars if the shape differs. designHeight(720) fills any shape instead, and you lay out by width.

push() saves position, rotation, scale, alpha, blend, filter and clip, and pop() goes back. Drawing that uses one image and

one blend mode goes to the GPU together, so sort by image where you can.

rich draws a paragraph with some of it marked: [color=orange], [b], [u] and [s], each ended with [/color], [/b],

[/u] or [/s], and [[ for a bracket itself. Colours are names (white, black, red, green, blue, yellow, orange, pink, purple,

cyan, gray) or #rrggbb. It wraps as paragraph does, and richHeight says how tall it will be. Both take an alignment, and

AlignJustify spreads each line but the last of a paragraph to fill the width, as a book's are.

Fonts drawn in pixels

Assets::font reads SSFN fonts, sharp at any size, and BMFont .fnt files too, with their one picture beside them, as BMFont,

Hiero and Littera write them: the size is a line's height, and 0 is as it was drawn. Assets::imageFont reads a picture of letters side by side with a column of one colour between each, given in the order they come:

Font@ pixel = Assets::imageFont("global:font/pixel.png", " ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789.,!?:-+=\'()/%", 21);
Font@ chunky = Assets::font("global:font/chunky.fnt", 36);

c.filter = FilterNearest;                          // pixels stay square
c.paragraph(pixel, "SPREAD TO FILL ITS WIDTH.", 50, 500, 560, White, AlignJustify);
c.filter = FilterLinear;

Their own colours are kept and tinted by the text's, so white shows them as they are. Both are in global:font, made by

engine/tools/make_pixel_fonts.py. The cook tool leaves pictures in a folder called font or fonts as they are, so that they

stay sharp and image fonts can be read pixel by pixel.

Sprite batches

A Batch keeps many sprites of one picture from frame to frame and draws them all at once: a crowd, bullets, a starfield, a map of tiles. Each has a place, a size, a turn about its middle, a part of the picture and a colour, and is changed by its number:

Batch@ stars = Batch(Assets::texture("global:picture/sprite-wisp.png"));
for (uint i = 0; i < 1500; i++)
    stars.addFrame(4, 2, i % 8, random(0, 1280), random(0, 720), 16, 16, Color(1, 1, 1, 0.3f));

stars.move(7, x, y, degrees);                      // in update()
stars.frame(7, 4, 2, frame);
c.batch(stars);                                    // in draw(): all of them, moved and tinted if asked

The Curves and Batches demo moves fifteen hundred every frame, at 60 frames a second on the original Xbox.

Polygons, paths, meshes and masks

polygon fills up to 256 corners, either way round and concave too, as long as its sides don't cross; polygonLine is its

outline and polyline lines through points, both mitred where they turn and bevelled where that would be sharp. ellipse and

ellipseLine are circles stretched.

mesh draws triangles of a picture: a point and where in the picture it comes from (uvs, 0 to 1 across it) for each corner,

three indices to a triangle, or a fan from the first point without them. A colour for each point tints it, and with no picture it is coloured triangles. A flag that waves, cloth, water, a picture wrapped round a shape.

A mask hides what is drawn outside a shape, or inside it:

c.mask();                                         // what is drawn now marks the mask, and isn't seen
c.circle(spot.x, spot.y, 80, White);
c.text(font, "NEXGEN", 640, 300, White, AlignCenter);   // text and pictures mark their shapes, not their squares
c.masked();                                       // only what is inside it is seen; masked(false) for outside
c.image(scene, 0, 0, 1280, 720);
c.unmask();

Each mask() starts a new one. A mask doesn't last into or out of a picture being drawn into, or into the next frame. On every GPU; the Paths and Masks demo has them all.

Pictures to draw into

Assets::picture(width, height) makes a blank picture of its own. Between c.beginPicture(picture) and c.endPicture(),

everything drawn goes into it rather than onto the screen, 3D included; then it is drawn like any other picture:

Texture@ map = Assets::picture(320, 320);

void draw(Canvas@ c)
{
    if (c.beginPicture(map, Color(0, 0, 0, 1)))     // cleared to a colour first, and its own pixels are the design
    {
        Space::camera(Vec3(0, 20, 0.01f), Vec3(0, 0, 0));
        Space::draw(c);                              // the world from above
        c.endPicture();
    }
    Space::camera(eye, look);
    Space::draw(c);
    c.image(map, c.width - 340, 20, 320, 320);       // a minimap
}

A minimap, a screen in a room, a mirror, or something drawn once and shown many times. One is drawn into at a time; effects, bloom and grading are for the screen. Up to 2048 pixels a side, and 1024 on the original Xbox; the Pictures demo has one.

Pixels

Pixels is a picture a script reads and writes one pixel at a time: made blank, read from a file with Assets::pixels, or the

last frame shown with App::screenshot(). Its texture draws it, sent to the GPU again when a pixel has changed:

Pixels@ board = Pixels(96, 54, Black);
board.set(10, 4, Yellow);
Color under = board.get(10, 4);
c.filter = FilterNearest;                          // sharp, drawn ten times as big
c.image(board.texture, 0, 0, 960, 540);

Pixels@ shot = App::screenshot();                  // in update(), not draw(); null on the Xbox 360
if (shot !is null) shot.save("saved:shot.png");    // a PNG with the saves; Assets::pixels("saved:shot.png") reads it

paste puts one on another, copy makes another, and png() is the PNG file in a string, to send. Up to 2048 a side. The Life

demo draws Conway's Life this way.

Scenes

Canvas draws whatever you tell it to each frame. For things that move, collide and come and go, let the engine keep them:

Entity@ rock = Scene::spawn(Vec2(640, 100));
rock.image(texture);
rock.circle(30, 1);              // a collider in group 1
rock.velocity = Vec2(0, 80);

void draw(Canvas@ c)
{
    c.design(1280, 720);
    Scene::draw(c);
}

A handle is always safe: once an entity has been destroyed its alive is false, and nothing done to it has any effect. One can be attached to another and moves with it. A behaviour is a script on an entity:

class Rock : Behaviour
{
    int health = 3;
    void update(float dt) { entity.rotation += 40 * dt; }
    void onHit(Entity@ other)
    {
        other.destroy();
        if (--health == 0) entity.destroy();
    }
}

rock.add(Rock());

onHit is called when its collider begins to touch one in a group that it hits.

Scene files

What things are like is better kept in a file. Scene::load("asset:scene.json") reads one:

{
  "groups": ["player", "rock", "shot"],
  "particles": {
    "dust": { "life": [0.3, 0.8], "speed": [20, 120], "size": [20, 4], "color": "#c0a080", "blend": "alpha" }
  },
  "prefabs": {
    "rock": { "image": "asset:rock.png", "circle": 30, "group": "rock", "hits": ["shot"], "spin": 40, "behaviour": "Rock" },
    "boulder": { "base": "rock", "scale": 3 }
  },
  "entities": [ { "prefab": "boulder", "position": [300, 200] } ]
}

and then Scene::spawn("rock", position) makes one. A name that means nothing is an error with its line. Files are reloaded with

--dev, like scripts.

Maps

A map is rows of letters, and a legend says what each is: a tile's number, or a prefab to spawn there.

"map": {
  "tile": 32, "solid": [1], "platforms": [2],
  "colors": { "1": "#5b3a24", "2": "#a8763e" },
  "legend": { "#": 1, "=": 2, "o": "coin", "H": "hero" },
  "rows": [
    "      o   ",
    "     ===  ",
    " H        ",
    "##########"
  ]
}

With "image" and "sheet" it is drawn from a picture instead of colours.

A tile can be a terrain, which joins up with its neighbours: with "terrains": { "2": 1 }, tile 2 is drawn with one of 16 frames of the sheet from frame 1, chosen by which of its sides meet more tile 2: up 1, right 2, down 4 and left 8, added up. So water gets its shores, and a path its bends, wherever they are painted, and Scene::setTile joins them up again as it goes. Past the map's edge counts as more of it. A map drawn only in colours edges its terrains instead, lit along the top and shadowed along the bottom, with rounded outer corners. Scene::terrain(tile, firstFrame) does the same from a script, and the Tiles demo has both, to paint on.

Scene::path(from, to, way) finds a way round the solid tiles: the corners of it, as straight as it can be, ending where it was

asked to go. It goes diagonally too, but never across a corner, unless it is told to keep to straight steps. Scene::blocked says whether a solid tile is at a place.

Lights

Scene::ambient is the light everywhere: white, as it starts, is no lighting at all, and anything darker turns it on. Then an

entity's light(colour, radius) lights what is round it, fading to nothing at the edge, and solid tiles cast shadows from it, as does any collider made an occluder:

Scene::ambient = Color(0.07f, 0.07f, 0.13f);       // night
hero.light(Color(1, 0.85f, 0.6f), 260);            // a lantern that goes where it does
crate.box(44, 44);
crate.occluder = true;                             // its shadow moves with it
Scene::lightLayer = 5;                             // layers above 5 are drawn after the light, bright: flames, sparks

Lights add up, and are multiplied over what is drawn, so a red light on blue shows dark. light(colour, 0) puts one out. The Lights demo has torches that flicker, crystals of colour, and crates and a pillar that cast moving shadows. BlendMultiply is there for drawing of your own, too.

Physics

There are two kinds. A solid body is stopped by walls and tiles and never turns: use it for characters, with onGround,

onWall and onCeiling. A body with mass is rigid: it pushes, stacks, bounces and turns. Scene::join pins two together, for

chains, hinges and wheels.

A collider is a circle, a box, a convex polygon of up to 8 corners (made convex if it isn't), or a chain: lines through up to 256 points that never move, for ground with hills and slopes, hit from either side. Characters stand on a chain's gentle parts, walk up and down them, and are stopped by its steep ones; to them a polygon is the box around it. A wall with oneWay is solid only from above: what is under it jumps up through it and lands on it, characters and rigid bodies alike.

Joints hold rigid bodies together, or to the scene where the second is null. Bodies joined together pass through each other:

Scene::hinge(wheel, car, wheel.position);                  // turns freely
Scene::hinge(door, null, hingePlace, -80, 80);             // between two angles, in degrees
Scene::motor(wheel, 700, 4e4f);                            // driven: degrees a second, and how strongly
Scene::weld(a, b, between);                                // as one
Scene::rope(lamp, null, lamp.position, hook, 120);         // no further apart than a length
Scene::spring(bob, null, bob.position, hook, 2, 0.2f);     // bounces twice a second, settling slowly
Scene::slider(lift, null, lift.position, Vec2(0, 1), -200, 0);   // along a line, between two places
Scene::drag(rock, mouse);                                  // pulled softly, as a hand would; dragTo moves it on
Scene::wheel(wheel, buggy, Vec2(0, 1), 4, 0.7f);           // turns freely, sprung up and down: four bounces a second
Scene::pulley(lift, weight, top1, top2, lift.position, weight.position);   // over two fixed places: one up, one down
Scene::gear(big, small, 2);                                // small turns twice as far, the other way
Scene::friction(puck, null, 1);                            // the ground seen from above: slows it, as hard as its weight
Scene::follow(cart, balloon, 3);                           // pushed to where it is now from cart, wherever cart goes
Scene::unjoin(rock);                                       // every joint it is in

Scene::motor drives wheels as it does hinges. followTarget says where from the first the second is pushed to now.

Scene::contact(a, b, at, normal, impulse) says whether two touched in the last step, where, which way and how hard: for a knock

as loud as the hit, or sparks where it was. The Contraptions demo has a car on hills, a lamp on a spring, a weight on a rope, a block on a rail, a door, and platforms that balls come up through; the Machines demo a buggy on sprung wheels that a balloon follows, a lift on a pulley that rocks weigh down, and a train of gears.

Three dimensions

The same entities can be in space: x right, y up, z towards you, in metres. Space::spawn puts one there, and behaviours, parents, groups, onHit and lifetime work as they do on the plane.

Model@ robot = Assets::model("global:model/robot.glb");
Entity@ hero;

void onEnter()
{
    Space::ground(0);
    Space::sky(Color(0.2f, 0.45f, 0.85f), Color(0.7f, 0.85f, 0.95f));
    @hero = Space::spawn(Vec3(0, 0, 0));
    hero.model(robot);
    hero.animate("idle");
}

void update(float dt)
{
    Space::camera(hero.place + Vec3(0, 3, 6), hero.place + Vec3(0, 1, 0));
}

void draw(Canvas@ c)
{
    c.designHeight(720);
    Space::draw(c);                        // all of the screen, or part of it
    c.text(font, "In front of it", 40, 40);
}
To look likeUse
A modelmodel, and animate("walk") to play one of its animations, changing smoothly from the last
A simple shapeshape(SolidBox, Red): a box, ball, cylinder, cone, ring, capsule or sheet
A mesh of your ownmesh, with a Mesh built from boxes, balls and triangles
A soft lightglow. light is what lights other things: the four strongest reach each thing

A model is a glTF (.glb or .gltf), FBX, OBJ, STL or PLY file, with up to 128 bones and 65536 vertices, and the files it names in its own folder. Anything but a .glb is turned into one as it loads; the cook tool does it beforehand, and has to for an FBX on the original Xbox. FBX and glTF bring bones and animations; OBJ brings materials and pictures; STL and PLY are shapes. The engine makes two simpler versions as it loads, and draws those when it is small on the screen. What can't be seen isn't drawn.

Space::sun, ambient, sky, fog and shadows set the scene. Shadows are the shape of what casts them, on the original Xbox too,

where the land casts none.

Mixing animations

animate plays one animation at a time. A model can do more:

robot.animateBlend(array<string> = { "idle", "walk", "run" }, array<float> = { 0, 1.5f, 4 });  // each at a point
robot.blendBy = speed;                                            // between two points, some of each, in step
robot.animateLayer("wave", "chest");                              // over the top half, on top of the rest
robot.stopLayer();
robot.rootMotion = true;                                          // the animation moves it, so its feet don't slide
robot.lookAt("head", ball.place);                                 // the head turns toward a place, up to 75 degrees
robot.lookAway();
  • Blends mix animations by a number, usually speed: idle at 0, walk at 1.5 metres a second, run at 4. Between two points the robot is some of each, and both are kept at the same point of their steps, so the feet don't stumble. animate changes back.
  • A layer plays an animation over one bone and every bone that hangs from it: waving with "chest" while the legs keep walking. It comes in and goes over a quarter of a second; layerPlayed says when one that doesn't loop has finished.
  • Root motion moves the whole thing as far as the animation carries its highest moving bone along the ground, which way it faces, so a stride made in a modelling program covers exactly the ground its feet do. A walker so moved still stops at walls.
  • Looking turns a bone after the animation, smoothly, and can be asked every update as the place moves.

The Moves demo has one of each, and the robot's "stride" is a walk that goes forward, for root motion.

robot.reach("hand.r", place) bends a limb's two bones, over whatever it plays, so that its end touches a place: a hand on a lever,

a foot on a step. Up to four at once; amount 0 lets one go. In the Moves demo, Fire makes the robots reach for the drone.

For more than a few animations, #include "global:states.as" brings in AnimationStates: states, each an animation, and links between them, with how long each change takes and whether it waits for the first to finish. travel goes the shortest way along the links, playing each state between, and a state that doesn't loop can say what comes after it:

AnimationStates moves(robot);
moves.add("idle");
moves.add("walk");
moves.add("leap", "jump", false, "idle");    // jumps once, then idles
moves.link("idle", "walk", 0.2f, true);      // both ways
moves.link("walk", "leap", 0.1f);
moves.start("idle");
// each update:
moves.update(dt);
moves.travel(jumping ? "leap" : speed > 0.1f ? "walk" : "idle");

Ragdolls

ragdoll(true) makes a model go limp. It gets a body for each bone that moves some of its skin, sized from that skin and pinned

where the bones meet, and each swings no more than about 57 degrees from how it sits on the one above. It falls from the pose it was in, carried on as it was moving, plus whatever push you give it:

robot.ragdoll(true, away * 4 + Vec3(0, 2, 0));   // knocked over
robot.push(blow, hitPlace);                      // limp, a blow moves the limb nearest the place
robot.ragdoll(false);                            // gets up where it lies, into what it plays, over 0.6 seconds

While it is limp its own collider isn't there, what hits one of its limbs (a ray, say) hits it, and its place follows where it lies. The robot has a dozen bodies; a few robots at once suit the original Xbox. The Topple demo knocks robots off a ledge.

Holding things, and joints

attach(parent) makes one thing move with another. attach(parent, "hand.r") makes it move with one of the parent's bones instead,

through every animation: a sword in a hand, a hat on a head, a light held up. bones and bone(i) list a model's.

Bodies with mass can be joined, to each other or, with null, to the world, at places in the world:

Space::join(link, above, top);                                   // pinned, free to turn: chains
Space::hinge(door, null, Vec3(0, 1, 0), Vec3(0, 1, 0));          // turning about an axis: doors, lids, wheels
Space::rope(seat, null, Vec3(5, 1.3f, 0), Vec3(5, 6, 0));        // no further apart than now: it pulls, never pushes
Space::spring(weight, null, Vec3(3, 3, 0), Vec3(3, 6, 0), 40, 1, 2);  // stiffness, damping and length

A joint goes when either thing does, or with Space::unjoin. The Tumble demo's *Swings* has one of each.

Joints can be held within limits, as a door stops against a wall or a neck turns only so far:

Space::hinge(door, null, Vec3(0, 1, 0), Vec3(0, 1, 0), 0, 100);   // opens one way, to 100 degrees
Space::join(head, neck, at, 40);                                    // swings no more than 40 degrees from how it hangs now

A ray can slip past what something thick would hit. Space::sphereCast moves a ball along a line instead, and says where its middle is when it first touches, and which way that faces; Space::spherePick says what it touched. For a character's way ahead, a thrown thing, or a camera kept out of walls:

Vec3 at, normal;
if (Space::sphereCast(target, wanted, 0.3f, at, normal))
    camera = at;                    // as near as it can be without going into the wall

A world to walk in

Space::land(21, 192, 1.5f, 34, 0.45f, true);   // a seed, squares, metres to each, height, roughness, an island
Space::flatten(0, 0, 40, 3);                   // somewhere to build
Space::water(0, Color(0.16f, 0.42f, 0.55f, 0.8f));

hero.capsule(0.35f, 1.6f, 1);
hero.colliderAt = Vec3(0, 0.8f, 0);            // its place is at its feet
hero.walker = true;

A walker stays upright, slides along walls, climbs small steps and pushes what has mass. Set motion each update, keeping its y so that it falls. Something with mass is a rigid body, as on the plane, with a sphere, cube or capsule collider; a collider with wall stops both. Space::raycast says what is on a line, including the land.

A world that streams

Space::endlessLand has no edge. Regions of 32 squares are made in the background as the camera comes near and go as it leaves. Ask

which have come, fill them, and let what is in them go with them:

int x, z;
bool arrived;
while (Space::nextRegion(x, z, arrived))
    if (arrived)
        Space::load("asset:region_" + x + "_" + z + ".json", Vec3(), true);   // true: streamed

A region may come from a file, or be made up from its numbers so that it is the same each time. A file lists entities:

{ "entities": [
  { "model": "global:model/oak.glb", "place": [4, 0, 2], "onLand": true, "angles": 90, "size": 1.2, "capsule": [0.3, 4], "wall": true },
  { "shape": "box", "color": "#b08048", "place": [3, 0.5, 1], "cube": [1, 1, 1], "mass": 5 },
  { "glow": 2, "light": [1, 0.7, 0.3], "range": 8, "place": [0, 3, 0] }
] }

Space::make makes one entity from a Json of the same kind. The showcase's Scene editor makes such files: fly about, add

things, move, turn, size and colour them, shape and paint the land, lay roads, join caves together, set the sky and the fog, then walk, drive or fly through the place, and save it; there can be several. It is a screen like any other, in

showcase/editor, and can be taken for your own tools. Models of your own appear at the end of its list: drop them on the window,

or put them in the folder own beside the saves, or in media/own on the original Xbox. Names there are small letters, digits, dots and dashes.

Using a scene in a game

A screen can include files of script that are shared: #include "global:scene.as" brings in Level, which makes a scene just as the editor does, land, sky, roads and all:

#include "global:scene.as"

Level level;
void onEnter() { level.load("asset:village.json"); level.set("health", 100); }
void update(float dt)
{
    string out = level.update(dt, player);          // "file|arrival" when the player went through a way out
    if (level.isOn("gate") && score > 10)
        level.show("treasure", 0.8f, "rise");       // hidden until now: it grows, rises or drops in
}
void draw(Canvas@ c) { Space::draw(c); level.drawHud(c); }

Anything with a name can be found (level.find), shown, hidden and switched on and off. Triggers are boxes that do something when someone goes into them, or a shot lands in them: show or hide a thing, switch something on or off, play a sound, or only tell the screen, through level.onTouch. Ways out lead to another scene, to an arrival of a name there. The HUD shows bars and text by name, set with level.set. On endless land, what is in each region comes and goes with it.

The Lost key showcase is a whole game made this way: two scene files, a village at dusk and an island at night, say what is where, which trigger opens the stone ring and what the HUD shows. Its script only walks, follows, keeps the score, and remembers what was taken so it stays gone when you go back.

Land by hand

Land that has an end can be changed, while a game runs too, and things on it follow:

Space::raise(x, z, 6, 2);                            // a hill six metres round; less than 0 digs
Space::smooth(x, z, 6, 0.5f);
Space::level(x, z, 6, height, 1);                    // somewhere to build

Space::hole(x, z, 3) opens the land, so that there can be something under it: the cave pieces in global:model (cave-mouth,

cave-tunnel, cave-bend, cave-slope, cave-room and cave-end) meet on a grid of 4 metres. A model of your own whose name begins with one of those joins them in the editor, so an entrance can look

like anything. Road pieces (road-straight, road-bend, road-t, road-cross and road-end) meet on a grid of 8 metres. The sun doesn't reach what has a material whose name begins with indoors. Space::edges = true puts walls that can't be seen at the sides of the land.

Space::lines = true draws only the edges of triangles, to see how things are made.

Those who move by themselves

#include "global:ai.as" brings in Agent and Crowd. An agent is a walker with a role: a guard stands where it was

put and chases what it sees, a patrol walks a route of places, a wanderer walks about near home, and there are chase, flee, follow and still. It sees with a range and a field of view, and only what no wall is in front of; it hears noises the game makes; it searches where it last saw you, and goes back to what it was doing. Its state ("walking", "chasing", "searching" and so on) is there for animations and sounds, and onEvent tells the game when it spots, loses, catches or hears something.

Crowd crowd;

Ways round what is in the way come from the engine: Space::navigate(middle, size) works out where things can walk, in squares over a part of the world, and Space::path(from, to, way) gives the shortest way between two places, made as straight as it can be. In a scene file, a thing with a "role" moves by itself as the level's crowd, and a patrol's

"route" is the waypoints of that name; the editor has both. The Guards showcase is a game of getting past them.

Water

Space::water(height, color) fills everything below a height: clear in the shallows and dark where it is deep, the sky in

it at a low angle, and foam where it meets the land. Space::waterStyle sets how it moves: calm, sea, choppy (crests that lean and break white), storm, or cartoon (flat light and a hard line of foam). Or set it yourself with

waterWaves(height, length, speed, choppy), waterColors(shallow, deep) and waterFoam(shore, crests). The waves are moved

on the CPU, so they look and cost the same everywhere; a scene file says "seaStyle" in its sky, and the editor has it on the Sky tab. The Water showcase goes round an island in each style.

Mist, smoke and fire

Space::mist(middle, size, color, thickness, swirl, grain) puts a box of mist in the world that can be walked into: billows

of noise in three dimensions, drifting with the wind and soft at the box's edges. The colour's alpha is how much it hides; swirl is how fast it moves and grain how many metres its billows are. Low and wide it is a bank of fog over a valley; tall and grey over a fire it is smoke; small, orange and swift it is the fire's glow. It gives an id, for moveMist and

removeMist. It is drawn as slices that face the camera, coloured from a texture with three dimensions, which every

platform has, the original Xbox included; there, where there is less to fill the screen with, with fewer slices. The Mist showcase is a valley at dawn.

Blocks

Space::voxels(corner, across, high, deep, size) makes a world of blocks, up to 1024 across, 256 high and 1024 deep, each

size metres. It is empty until it is filled: setVoxel(x, y, z, kind) one at a time, fillVoxels a box, voxelBall a

ball (0 digs a hole), or voxelHills(seed, height, roughness, sea, caves) hills from a number, with grass and earth over stone, sand at the sea, snow on the tops and hollows under them. Kind 0 is nothing; 1 to 255 are kinds, coloured on top and on their sides by voxelColor (twelve to begin with: grass, earth, stone, sand, wood, leaves, brick, snow, planks, dark stone, gold, ice). voxelRay(from, to, cell, face, hit) finds the block a line meets and the face it goes into, so cell plus face is where a new block goes; voxelCell and voxelPlace turn places into blocks and back.

The blocks are kept in chunks of 16 each way, and only where there is something. Each is made into the faces that can be seen, side by side faces of the same kind joined into one, and corners darker where blocks crowd them: a new world is made a few chunks a frame, nearest first, and a block that is dug or built is seen at once. They are part of the land: walkers stand on them and bump into them, things fall onto them, and raycast meets them as group 0. The Blocks showcase is hills to dig and build in, in the first person; at 60 frames a second on the original Xbox too.

Wind

Plants lean with the wind: give a thing a sway, how far its top moves for each metre of height (about 0.02 for a tree, 0.15 for

global:model/grass.glb), or "sway" in a scene file. Space::wind = Vec3(1, 0, 0.4f) says which way it blows and how hard, and

gusts roll across a wood as a wave. The base stays where it is, it is only how things are drawn, and it costs the same on every platform. The editor gives trees, bushes and grass their sway when they are added.

Grass, impostors and sprites

Space::grass(Assets::model("global:model/grass.glb"), 3, 30) grows tufts over the land near the camera, so many to a

square metre and out to a distance: only where the land is green, flat enough and dry, coloured as the land is there, and bending in the wind. It is made a few squares at a time as you move, and again where the land is changed. A scene file says

"grass": 2.5, and the editor has it on the Land tab. On the original Xbox, where vertices can't be moved, it stands still.

Things with impostor = true are drawn, further away than Space::impostors metres, as a picture of themselves: made from the model when it is first needed, from four sides, and drawn with all the others that share it at once. A wood of two thousand trees costs about half as many triangles, and looks the same.

A sprite is a picture that stands upright and turns to face the camera, as the characters of old maze games did:

Entity@ wisp = Space::spawn(place);

Across the sheet is how it looks from each side, the first from in front and then going round to its left; which one is shown follows from where the camera is and which way it faces. In a scene file it is "sprite", with "views" and

"frames". The Wisps showcase is a maze of them, and the wisps in Guards run from you.

Files that players bring

Particles and sounds in space

Particles are described in a scene file, as on the plane, with lengths in metres. spread is in degrees: 90 is a cone, and 360 goes every way. They face the camera, are lit by nothing, and hide behind things.

Scene::load("asset:scene.json");                        // "particles": { "flame": {...}, "sparks": {...} }

What is heard fades with distance from the camera, and moves from one side to the other.

Shapes that melt

Space::field adds one of up to 24 shapes that are drawn by marching along rays, so that they join softly, cut each other and

reflect. They mix with meshes. Clear them and add them again each update to move them. The original Xbox makes triangles of them.

Shaders, bloom and grading

Effect@ tube = Assets::effect("global:effect/tube.fx");

An effect is one file, for every GPU that has shaders: Direct3D 11 and OpenGL now. The original Xbox has bloom but no such shaders; there, a line // xbox: lava in the file names something close that it can do: lava, dissolve, hologram or flag on a thing, and

tube, pixels, ripple, glitch, grade or ink over the picture. Without one, effect gives false and things are drawn as they are. A mistake in one is in the

log with its line, and it is left out.

Over the picture:

float4 effect(float2 uv, float4 color)
{
    float grey = dot(color.rgb, float3(0.3, 0.6, 0.1));
    return float4(lerp(color.rgb, float3(grey, grey, grey), values[0].x), 1.0);
}

On a thing:

#define MOVES                                     // only if it has move()
float3 move(float3 place, float3 normal, float2 uv)
{
    return place + normal * sin(time * 3.0 + place.y * 4.0) * values[0].x;
}

float4 paint(float4 color, float2 uv, float3 place, float3 normal, inout float glow)
{
    glow = max(glow, frac(uv.y * 8.0 - time));    // 1 is bright whatever the light
    return color;                                 // before it is lit
}

size, timeOf the picture in pixels, and seconds
values[0] to values[3]Sixteen numbers, set with Effect::set
depthAt(uv)After Space::draw, how far away what is there is, in metres; farthest for the sky

The last three rows are on GPUs where Space::depthEffects: Windows, Linux, macOS, the Xbox One and the Xbox 360. They are enough for god rays, fog by distance, outlines where things meet and the like: global:effect/rays.fx is god rays, written that way.

It is written as HLSL is, and every number with a point in it. float2 to float4, lerp, frac, saturate and fmod have their OpenGL names put in for you; keep to what both have. Don't name anything out, in, sample, texture, step, distance or any of the words in the table.

Blur, and finishing a view

c.blur(8) blurs all that has been drawn so far, about 8 pixels across on a screen 720 high, or only inside the clip: frosted glass

behind a pause menu, or a dream. It works on every GPU.

Where Space::depthEffects, each view in space can be finished from how far away each of its pixels is:

Space::occlusion(1, 0.6f);          // corners and creases darker, within 0.6 metres
Space::reflections(0.6f);           // wet floors and still water show what is around
Space::focus(5, 1, 12);             // sharp at 5 metres, 1 either side; 12 pixels of blur, with bokeh
Space::autoExposure(0.4f);          // brighter in the dark and darker in the light, gradually

Each takes 0 for none. Reflections show only what is on the screen and in what faces up; the further a pixel is from the focus, the more it is blurred, and the brightest spread into round bokeh. The Lens demo has them all, god rays and decals too, behind a frosted panel.

Grading

Look@ look = Look("dusk");         // or Look(), and settings of your own
look.saturation = 0.8f;
look.shadows = Color(0.3f, 0.4f, 1, 0.4f);   // bluer where it is dark; alpha is how much
look.load("asset:film.cube");      // a table from a grading program, first, if you like

void draw(Canvas@ c)
{
    Space::draw(c);
    c.bloom(0.3f, 0.8f);
    c.grade(look);                 // strength 0 to 1 is a second number
    c.text(font, "Not graded", 40, 40);
}

A Look is what each colour of the picture becomes. It has settings: exposure in stops, warmth and tint, contrast,

saturation, fade (blacks lifted, as old film), gamma, and colours for the shadows and the highlights. preset sets them all

to one ready-made: none, warm, cold, faded, noir, sepia, dusk, vivid, bleach or night. load reads a .cube 3D table, as Resolve, Photoshop and other grading programs write them, and colours go through it before the settings; apply gives what it makes of one colour, without the GPU.

Whatever it is, it is worked out once into a table of 32 by 32 by 32 colours, a texture with three dimensions, and again only when something about it changes. grade then looks each pixel up in it, in one pass over the screen: with a shader on Direct3D 11 and OpenGL, and on the original Xbox with its own texture stages, which can look a colour up in a table, so it costs little there too. Within a clip, only that part is graded. The Looks showcase shows them all, before and after, at 60 frames a second on the original Xbox.

Sound a script makes

Samples is sound as numbers, -1 to 1, written and read one at a time, and played like a sound: each play has a copy of its own.

Assets::samples reads a sound's own, to look at or change.

Samples@ zap = Samples(12000);                      // a quarter of a second at 48000 a second, one channel
float p = 0;
for (uint i = 0; i < zap.frames; i++)
{
    float t = float(i) / zap.frames;
    p += (1800 - 1500 * t) * 6.2831853f / 48000;    // falling in pitch
    zap.set(i, sin(p) * (1 - t));                    // and fading
}
zap.play();

An AudioStream plays sound as it is written, for a synthesiser, a tracker or an emulator: write as much as there is room for each frame. It holds so many seconds, as made; it is quiet while it has none, and plays out what it has after it is let go.

AudioStream@ out = AudioStream(48000, 1, 0.1f);
array<float> chunk;

void update(float dt)
{
    chunk.resize(out.room);
    for (uint i = 0; i < chunk.length(); i++)
        chunk[i] = nextSample();
    out.write(chunk);
}

The Synth demo plays an arpeggio this way, with a laser made from Samples, through every effect.

Input

Scripts ask for actions, not keys: up, down, left, right, accept, cancel, fire, alternate and menu. Players can change every one except menu; the Settings demo shows how. Input::move gives a direction from keys, d-pad or stick.

On the original Xbox, a USB keyboard and mouse work too, through an adapter in a controller port or its bottom slot: keys, typing and the mouse are read as they are on a computer, and the engine draws the pointer, since nothing else there does. Where there is only a controller, the stick can move a pointer instead, and A click with it: the player chooses that in Settings (Input::stickPointer, kept with the other settings), and a screen says it has a use for one with

Input::wantsPointer = true, as the scene editor does while editing. The stick and A then do nothing else, and a mouse

that moves takes over.

Pads rumble: Input::rumble(0.6f, 0.2f) shakes every pad for a fifth of a second, and Input::rumbleMotors(heavy, light, seconds, pad) sets the slow, heavy motor and the quick, light one each. It stops when the engine's menu opens and when the screen changes, and players can turn it off in Settings (Input::rumbleOn, kept with the other settings).

Paths and noise

A Path is a smooth way through points, passing through every one, for things to follow at a steady speed:

Path@ track = Path({ Vec3(0, 0, 0), Vec3(10, 0, 4), Vec3(20, 2, 0), Vec3(10, 0, -6) }, true);   // a loop
float along = 0;

void update(float dt)
{
    along += 6 * dt;                                    // metres a second, however far apart the points are
    car.place = track.at(along);
    car.angles = Vec3(0, atan2(-track.direction(along).z, track.direction(along).x) * 57.3f, 0);
}

On the plane, give it Vec2s with add and ask at2 and direction2. nearest says how far along it a place is closest.

noise(x, y, z) is smooth randomness, -1 to 1, with hills and dips about a unit apart and the same at the same place every time:

scale the place for bigger or smaller ones, and move through z for noise that changes over time. fractalNoise adds finer layers, for land, clouds and fire; noiseSeed picks another pattern.

A Curve is a Bezier curve, as drawing programs make: it starts at its first control point, ends at its last, and is pulled towards those between without passing through them. It is asked for by t, from 0 to 1:

array<Vec2> controls = { Vec2(80, 400), Vec2(140, 130), Vec2(380, 120), Vec2(580, 380) };
Curve@ road = Curve(controls);
c.polyline(road.points(64), 6, Gray);              // 64 places along it, to draw
Vec2 at = road.at(t), heading = road.slope(t).normalized();
Curve@ middle = road.part(0.4f, 0.6f);             // a curve of its own

triangulate cuts a polygon, concave too, into triangles, three corner indices each, for Canvas.mesh or convex pieces for

physics; isConvex says whether it bulges out at every corner. A Vec2 has length, normalized, distance, angle,

rotated, perpendicular and cross. toLinear and toGamma turn a colour into the light it stands for and back, to mix lights

as they really would.

Coroutines and tweens

A coroutine is a function that can wait:

void onEnter() { start(Coroutine(this.intro)); }

void intro()
{
    title.go(1, 0.5f, EaseOvershoot);
    wait(2);
    title.go(0, 0.3f);
    while (!title.done) nextUpdate();
    Screens::replace("game");
}

A Tween is a number that moves by itself. There is nothing to update: read value when drawing. go() starts from wherever it is, so changing course never jumps.

Threads

A coroutine shares the frame; a Thread doesn't. It runs a script file of its own, from its void main(), on a thread of its own, in an engine of its own: strings, arrays, maths, Json, Data and Random, and nothing that draws, plays or loads. It shares nothing with the screen but Channels: text passed one way or the other, first in, first out. Channels of the same name are the same, in every thread.

// asset:worker.as
void main()
{
    Channel jobs("jobs"), results("results");
    while (!Worker::stopping)                    // true as the screen closes
    {
        string job = jobs.demand(0.5f);          // waits for one, here only
        if (!job.isEmpty()) results.push(work(job));
    }
}
Thread@ worker = Thread("asset:worker.as");
Channel jobs("jobs"), results("results");

void onEnter() { worker.start(); jobs.push("level 3"); }

void update(float dt)
{
    string done;
    while (results.pop(done)) use(done);         // never waits
    if (!worker.error.isEmpty()) print(worker.error);
}

Numbers go as text and anything with parts as Json's. A thread is asked to stop, and waited for, when nothing holds it any more, as its screen closes: its demand and Worker::sleep end at once, and long loops should look at Worker::stopping. Up to 8 at once. System::processors says how many can truly run together: on the original Xbox one, so a thread there gets the time the screen leaves. The Threads demo draws the Mandelbrot set this way while the screen turns smoothly.

Networking

Nothing here waits: ask, and look each update at what has come. Who sends what is up to you, so never trust what arrives.

Playing together

A Room is a game on the local network, or on the internet with a meeting place. One player hosts; others find it by the game's name and join.

Room@ room = Room();

room.host("my game", "Sam");                  // or
room.find("my game");                         // ...and then, when room.found > 0,
room.join("my game", 0, "Alex");

Message@ m = Message();
m.writeInt(1);
m.writeVec2(position);
room.send(m, false);                          // false: quickly; true: for sure, and in order

for (Message@ m = room.receive(); m !is null; @m = room.receive())
    if (m.readInt() == 1)
        where[m.from] = m.readVec2();         // m.whole says whether it was all there

room.state is RoomIn once you are in, and RoomLost if the host goes. arrived() and departed() say who has come and gone. Use

quick messages for what is out of date in a moment, such as where things are, and sure ones for what happened.

Shared entities

Rather than saying where everything is yourself, share it: the room keeps an entity of yours alike in every other copy of the game, where it is, how it is turned, its frame, flip, alpha and whether it is shown, or in space its place, turn and animation.

room.share(ship, "ship");                     // this player's; the kind says what to make of it elsewhere

Entity@ make(const string &in kind, int player)   // makes this game's copy of another player's
{
    Entity@ e = Scene::spawn(Vec2(0, 0));
    e.rect(46, 22, colorOf(player));
    return e;
}

void update(float dt)
{
    room.sync(Copy(this.make));               // once a frame
}

sync says where this player's are, 20 times a second, and moves the copies of everyone else's smoothly after theirs, going on

the way they were going for a moment if a message is late; one that jumps a long way is jumped, not glided. Copies are hidden until it is known where they are. Whoever joins later is told of everything already shared, a copy goes when its original is unshared or destroyed, and all of a player's go when they leave. ownerOf(e) says whose an entity is. This travels on the room's own channel, alongside your messages, which still say everything else: who scored, what was picked up. A copy is placed by its owner, so give it no body of its own. The Arena demo shares each player's ship and the sparks it leaves.

Playing over the internet

Players on different networks meet at a meeting place: a machine every one of them can reach, such as a small server somewhere, running the engine with --meeting 27300 (no window, nothing else; it says now and then how many rooms and players it has). Give it to a room before hosting, finding or joining:

room.meet("games.example.com");               // or "1.2.3.4:27300"
room.host("my game", "Sam");                  // listed there, as well as on this network

A room that is hosted is listed there; find asks it as well as the local network, and foundFar(i) says which were found there. Joining one of those, the meeting place introduces the two players, so that each one's router lets the other's packets in, and they play directly; if a router won't have it, the meeting place passes their packets on, between those two only and only so much a second, and relayed(player) says so. The player can choose a meeting place once, in the settings, as

Net::meetingPlace, kept between runs; every room meets there unless it is told otherwise. A room whose host has let its port

(27310) through the router can also be joined by address, as room.join("my game", "games.example.com:27310", "Alex"), with no meeting place at all.

The web

Request@ request = Net::get("https://example.com/scores");

if (request.done && !request.failed)
    show(request.status, request.text);

Certificates are checked, against those in media/global/certificates.pem: a server that can't be trusted is refused, and error says why. An answer may be up to 4 MB. Net::post sends something.

A WebSocket stays open, for messages both ways with a web server: a chat, a lobby, scores as they change.

WebSocket@ socket = WebSocket("wss://example.com/chat");

if (socket.connected)
    socket.send("hello");
string message;
while (socket.receive(message))
    show(message);
if (socket.closed)
    show(socket.error);

It connects, sends and reads on a thread of its own, so nothing waits; wss:// is over TLS, its certificate checked as for Net::get. Messages may be up to 4 MB, and pings are answered for you.

Anything else

Connection is a stream of text over TCP, to a server or from those who connect to you; Datagrams sends short texts over UDP.

The window and the system

On a computer, Window changes the window; on a console there is only the screen, Window::available is false, and changing it does nothing:

Window::fullscreen = true;                 // over the whole screen, without a border; Alt and Enter too, on Windows
Window::title = "Level 3";
Window::resize(1600, 900);                 // its inside, in pixels, while it isn't full-screen
Window::vsync = false;                     // as many frames as it can make; consoles always wait for the refresh
Window::pointer = PointerHand;             // over a button; PointerText over a field, PointerCrosshair to aim
if (!Window::focused) pause();             // the player is in another window
if (Window::ask("Quit", "Leave without saving?")) Screens::home();   // the system's own box, waited for

System is the same on every machine:

System::clipboard = code;                  // copied, to paste elsewhere; a console keeps one of the game's own
string words = System::language;           // "en", "ja": which words to show; System::locale is "en-GB"
uint threads = System::processors;
System::open("https://example.com");       // in the browser, or a file in what opens it
int left = System::battery;                // 0 to 100, or -1 without one; System::charging
string now = System::clock(true);          // "4:55 pm", as the machine's clock is set; System::hour and minute too

On Linux the clipboard needs wl-copy, xclip or xsel, and messages zenity, kdialog or xmessage. The System demo has them all.

On Windows the window's frame is dark when Windows' apps are set to look dark, and changes when they do. Windows 11 lets a game dress it to suit its look:

Windows::titleLook = TitleDark;                     // or TitleLight; TitleSystem follows Windows, as it starts
if (Windows::titleColors)                           // Windows 11: colours, border and corners
{
    Windows::titleColor = Color(0.16f, 0.1f, 0.22f);  // the title bar; anything see-through puts back the system's
    Windows::titleTextColor = Color(1, 0.7f, 0.25f);
    Windows::borderColor = Color(1, 0.5f, 0.2f);      // or Windows::noBorder = true
    Windows::corners = CornersSquare;                 // CornersRound, CornersSmall, CornersSystem
}
if (Windows::backdrops)                             // Windows 11 from its 2022 update
    Windows::backdrop = BackdropMica;               // BackdropAcrylic, BackdropTabbed, BackdropNone

What a Windows can't do is left as it is, and nothing goes wrong asking; elsewhere they do nothing.

What only an Xbox can do

Xbox::available is true on an original Xbox. Its temperatures, fan, light, tray, drives and files are there, as are ways out:

if (Xbox::available)
{
    string cpu = formatInt(Xbox::cpuTemperature) + " C";
    array<string>@ games = Xbox::folders("E:\\Games");
    Xbox::launch("E:\\Games\\Thing\\default.xbe");   // or toDashboard(), toFirmware(), restart(), powerOff()
}

Xbox::busRead and busWrite reach anything on the SMBus but the console's settings, where a mistake can't be undone. Elsewhere

readings are -1 or empty and the rest do nothing.

Files can go to and from the console over the network. Nothing listens until it is asked to, and nothing can be changed unless that is asked for too:

Xbox::startFtp("xbox", password, false);             // drives E, F and G; true lets it write

Only machines on the same network are answered. FTP hides nothing from them, so start it when it is wanted and then Xbox::stopFtp().

Files and JSON

Json reads and makes JSON. What isn't there is null, and can be asked things all the same:

Json j;
string error;
if (j.parse(Assets::read("asset:level.json"), error))
{
    float x = float(j["player"]["place"][0].number());
    Vec3 at = j["door"].vec3();                      // [x, y, z]
}
j.set("score", 40);                                  // text, flags, places, colours and other Json too
Assets::write("asset:level.json", j.write());

Assets::write writes only a screen's own asset: files that end in .json. With --dev it is the file in the media; otherwise

it is kept with the saves, on consoles too, and Assets::read and Space::load read that one from then on. Assets::forget goes back to the one that came with the screen.

Bytes

A string holds any bytes, and Data works on them: compress and uncompress in zlib's format, which most languages read;

md5, sha1 and sha256, fingerprints as hex digits; base64 and unbase64, hex and unhex, to carry bytes as text.

string packed = Data::base64(Data::compress(level.write()));   // small enough to share as a code
string sum = Data::sha256(Assets::read("asset:level.json"));  // has it changed?

gzip and gunzip make and read .gz files; deflate and inflate are the same with nothing round it, as some servers and

formats want; crc32 is the check that zip, gzip and PNG files keep.

Packed lays numbers and text out in bytes as a file format or another program wants them, and reads them back in the same

order: bytes, 16, 32 and 64-bit whole numbers, floats, doubles, text that ends in a zero or fills so many bytes. It is little-endian unless bigEndian is set. whole is false if more was read than there was.

Packed header(Assets::read("asset:level.bin"));
uint magic = header.readU32();
int width = header.readI16(), height = header.readI16();
string name = header.readFixed(16);

A Zip reads a zip file's files, or puts some together to make one: a level pack, a player's mod, a save with its pictures.

Assets::pixelsFrom turns a picture's bytes, from a zip or anywhere else, into Pixels:

Zip pack(Assets::read("own:mod.zip"));
for (uint i = 0; i < pack.count; i++)
    if (pack.name(i).findLast(".png") > 0)
        pictures.insertLast(Assets::pixelsFrom(pack.read(pack.name(i))));

Zip out;
out.add("level.json", level.write());
out.add("shot.png", App::screenshot().png());
string file = out.bytes;                           // any zip program opens it

Random numbers from a seed

random() and randomInt share one generator. A Random is one of a script's own: the same seed gives the same numbers in the

same order on every machine, for a world made from a number, a replay, or the same deal twice. normal(mean, deviation) is mostly near the mean and seldom far from it, in a bell curve; randomNormal is the same from the shared one. state is where it has got to, as text to keep in a save and give back.

Random r(seed);
float height = r.normal(1.7f, 0.1f);
int card = r.randomInt(0, 51);

On the original Xbox

  • 64 MB in all. Images and fonts may take 20 MB and sounds 6 MB by default.
  • A scene may have 4096 entities and 1500 particles at once; elsewhere 16384 and 8000.
  • Build the disc with the cook tool, which makes images a quarter to an eighth of the size in memory and sounds a quarter, under the same names.
  • Three dimensions use the fixed pipeline: lights are worked out at corners, so give a floor plenty of squares. Ray-marched shapes become triangles. Effects are stand-ins.
  • Live reload works with a dev folder beside the title: copy changed scripts to the console over the network and the screen reloads. The debugger works over the network too: put a debug folder there, or call App::debugger(), and attach to the console's address.
